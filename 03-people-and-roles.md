# 3. People & Roles

## Overview

An Agent Hackathon requires coordination across three organizations. Getting the right people in the right roles is critical to both event success and post-event conversion.

## Microsoft Organization

| Role | Description | Main Objectives | Before | During | After |
|------|-------------|-----------------|--------|--------|-------|
| **Partner Team (PM/PDM/PTS)** | Orchestrates the project & impact | Help connect with internal stakeholders; follow up | ✓ | ✓ | ✓ |
| **Partner Solution Architect (PSA)** | Microsoft architect ensuring technical alignment | Scope and validate use cases; maximize Microsoft tech usage | ✓ | ✓ (optional) | |
| **Jury Member** | Evaluates final pitches (Microsoft representative) | Score, give feedback, select winning team | | ✓ | |
| **Microsoft Account Team (AE/CSM)** | Follows up on opportunities post-event | Track customer interest; engage in transformation; drive follow-ups (O.O., MCI) | | ✓ | ✓ |
| **Microsoft Expert (GBB/STU)** | Product specialist | Evangelize advanced features; inspire teams; support innovation | | ✓ | |

### PSA Responsibilities in Detail

The PSA role is a **mandatory** touchpoint (via technical call, Step 6):

1. **Before**: Scoping call to validate use cases, ensure technical feasibility, align on environment
2. **During**: Optional on-site presence to support technical challenges
3. **Key value**: Prevents scenarios that push against Copilot Studio limitations; steers toward achievable outcomes

Request PSA support via [PMX](https://aka.ms/pmx).

## Partner Organization

| Role | Description | Main Objectives | Before | During | After |
|------|-------------|-----------------|--------|--------|-------|
| **Business Analyst** | Partner expert guiding business ideation | Refine use cases; ensure business relevance; support team ideation | ✓ | ✓ | |
| **Developer** | Technical expert supporting agent build | Assist with Copilot Studio; build and troubleshoot agents | ✓ | ✓ | |
| **Event Coordinator** | Owner of logistics and planning | Ensure smooth event flow; manage timeline and resources | ✓ | ✓ | ✓ |
| **Jury Member** | Evaluates final pitches (partner representative) | Score, give feedback, select winning team | | ✓ | |
| **Account Team** | Connects with customers & follows up | Track customer interest; drive follow-ups (O.O., MCI) | | ✓ | ✓ |

### Partner Staffing Per Table

> ⚠️ **Field Insight:** Each table needs **1 business person + 1 technical person** from the partner. The business person manages the scenario and customer needs; the technical person handles Copilot Studio configuration and tricky parts. Give customers the easy parts (e.g., prompting their agent) while the partner pre-configures the complex setup.

**Minimum per table**: 1 functional expert + 1 technical expert coach

## Customer Participants

| Role | Description | Main Objectives | During |
|------|-------------|-----------------|--------|
| **Business Participant** | Business profile who knows processes | Bring real-life challenges; ideate agent solutions; share feedback | ✓ |
| **Strategic Tech Contact** | CTO/CIO -1 level | Bridge business ideas to technical feasibility; smooth path to production | ✓ |

### Customer Attendee Selection

> ⚠️ **Field Insight:** Use cases drive attendee selection — not the other way around. If scenarios are process-specific, you need people who understand those processes. Define use cases first, then determine whom from the customer should be invited.

**Recommended per customer organization**: 2 people
- 1 business role (knows the processes, can ideate)
- 1 strategic tech role (CTO/CIO -1; understands business requirements AND is responsible for technology)

**Why the strategic tech role matters:**
> ⚠️ **Field Insight:** Without a tech-strategic person present, business people have great ideas but when they go back to IT teams, the response is "we can't do that — no governance in place." Having someone who understands both business AND technology smooths the path from hackathon to production. This is NOT a low-level admin.

**Additional: IT Admin on-call**
- When using customer environments: have an IT admin available (phone/Teams), not necessarily on-site
- Role: resolve access, connectivity, licensing issues ("break glass person")
- NOT required if using Spektra or partner-managed environments

### Who Should NOT Attend
- Pure IT admins (unless running in customer environment and they're on standby)
- People without decision-making authority or process knowledge
- Attendees who "just want to watch" — everyone should participate

## Attendee Mix and Table Composition

### Table Organization Options

| Approach | Description | Best For |
|----------|-------------|----------|
| **By Industry** | Each table = one industry (Banking, Healthcare, etc.) | Multi-customer events; industry-specific solutions |
| **By Function** | Each table = one business function (HR, Finance, etc.) | Cross-industry events; function-specific agents |
| **Mixed** | Combination of industry and function | Maximum flexibility |

### Table Composition (4–6 people per table)

- Multiple customers from similar industry/function
- 1 partner functional expert (table coach)
- 1 partner technical expert
- Mix of business and technical profiles across customers

> 🔍 **[Enrichment]** From event recaps: **Mixed business + technical tables outperform single-role groups**. The diversity of perspectives leads to more practical, implementable solutions.

### Attendee Requirements by Environment Type

| Environment | Technical Attendee Needed? | Admin On-Call? |
|-------------|---------------------------|----------------|
| Spektra (dummy tenant) | Nice to have, not required | No |
| Partner-managed | Nice to have | Partner handles |
| Customer environment | **Yes** — strategic tech required | **Yes** — IT admin on-call |

## It Is Not Required to Be Technical

Attendees do NOT need to be technical. This is an **ideation** event. Each table has partner technical support. The afternoon hands-on session is guided, and participants can focus on prompting and scenario design rather than deep configuration.
