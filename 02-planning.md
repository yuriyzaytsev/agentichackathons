# 2. Planning & Timeline

## Retroplanning Overview (10 Weeks)

| When | Step | Key Actions |
|------|------|-------------|
| **8 weeks before** | Build the Framework | Target customers, focus (industry/function), event positioning, form v-team |
| **7 weeks before** | Schedule the Event | Lock venue/date, briefing pack, digital comms plan |
| **6 weeks before** | Registration | Launch registration form, track invitations, confirm attendance |
| **4 weeks before** | Prepare Use Cases + Environments | Demo environments, one scenario per table, data preparation |
| **4 weeks before** | Presentation Validation | Book speakers, validate content, confirm jury |
| **3 weeks + 1 week before** | Technical Call | PSA scoping calls (mandatory), validate use case feasibility |
| **1 week before** | Final Preparation | Agenda shared, dry run, pitch flow aligned |
| **D-Day** | Hackathon Day | Execute: presentations + hackathon + awards |
| **+1 week** | Follow-Up | Summarize scenarios, evaluate interest, propose next steps |
| **+1 month** | O.O. Engagement | Execute follow-up workshops, create leads, nominate to MCI |

## Step 1: Build the Framework (8 Weeks Before)

### Key Decisions

1. **Industry vs. Function focus**: Will tables be organized by industry (Banking, Healthcare, Manufacturing...) or by business function (HR, Finance, Operations...)?
2. **Target customers**: Define which customers to invite based on pipeline, maturity, and potential
3. **Event positioning**: Name, visual identity, co-branding with partner
4. **Internal v-team**: Identify Microsoft & partner stakeholders

### Checklist
- [ ] Align with partner on event objectives
- [ ] Define event name, visual identity, target audience
- [ ] Form the internal Microsoft & partner v-team
- [ ] Register event on [EMEA Partner Event Registration](https://aka.ms/EMEAPartnerEventReg)

> ⚠️ **Field Insight:** Start with use cases BEFORE targeting customers. The use cases determine what people you need — if scenarios are process-specific, you need the people who understand those processes. Don't work out use cases at the event itself.

## Step 2: Schedule the Event (7 Weeks Before)

### Checklist
- [ ] Confirm date and venue (partner/Microsoft office or external)
- [ ] Create internal briefing pack
- [ ] Plan digital communication campaign
- [ ] Block speaker calendars

### Venue Considerations
- Prefer partner or Microsoft offices to minimize cost
- External venues may need pull-up banners/branding
- Ensure reliable WiFi and power for all attendees
- Plan table layout for 4–6 people per table + coach space

## Step 3: Registration (6 Weeks Before)

### Checklist
- [ ] Publish registration form
- [ ] Send invitations to target customers
- [ ] Register event on [EMEA Partner Event Registration](https://aka.ms/EMEAPartnerEventReg)

### Registration Form Must Capture
- Customer business industry
- Customer business function
- Role (business/technical profile)
- Company size / maturity indicators

### Attendee Recommendations
- Invite **2 persons per organization**: 1 technical profile + 1 business role
- Partner is responsible for tracking invitations and confirming attendance

> ⚠️ **Field Insight:** The right attendee mix is critical. Invite CTO/CIO-1 level (strategic, understands business AND technology), not full-on admins. Without a "strategic tech" person, great hackathon ideas die when handed to implementation teams who say "we can't do that — no governance in place."

## Step 4: Prepare Use Cases + Demo Environment (4 Weeks Before)

This is one of the **most critical steps**. See [Use Cases & Scenarios](04-use-cases-and-scenarios.md) for detailed guidance.

### Checklist
- [ ] Prepare one pre-built agent scenario per table/topic
- [ ] Set up demo environments (Spektra, CDX, or customer)
- [ ] Prepare dummy data for each scenario
- [ ] Create one Power Platform environment per table
- [ ] Validate scenarios work technically end-to-end
- [ ] Prepare backup/simple use cases to spur discussion

> ⚠️ **Field Insight:** Environment readiness is the #1 risk factor. In Stockholm, it was "super important that environments were set up correctly, everyone was directly on board." Multiple hackathons have reported access issues on D-Day. Test EVERYTHING in advance.

## Step 5: Presentation Validation (4 Weeks Before)

### Checklist
- [ ] Validate final agenda with all stakeholders
- [ ] Confirm speakers and jury members
- [ ] Prepare scoring criteria and jury evaluation sheet
- [ ] Ensure ROI/business value messaging is embedded in presentations
- [ ] Include licensing information in presentations
- [ ] Align partner and Microsoft on who presents what — use a shared deck

> ⚠️ **Field Insight:** Create ONE shared presentation deck where both Microsoft and partner contribute slides. Without this, both sides independently prepare similar "what are agents" content, creating redundancy and wasting attendee time. Agree up front on topic ownership. (May 2026, adesso hackathon debrief)

> ⚠️ **Field Insight:** Make sure there's an ROI message including licensing in the presentations. Don't just show the tech — show the business value.

## Step 6: Technical Call (3 Weeks + 1 Week Before)

### Checklist
- [ ] Schedule and conduct PSA scoping call (**mandatory**)
- [ ] Validate use cases from technical perspective
- [ ] Confirm environment access works
- [ ] Align on Copilot Studio capabilities vs. limitations
- [ ] Request PSA support via [PMX](https://aka.ms/pmx)

### PSA Role in Technical Call
- Scope and validate use cases
- Maximize Microsoft technology usage
- Confirm technical feasibility
- Identify potential issues before D-Day

## Step 7: Final Preparation (1 Week Before)

### Checklist
- [ ] Final agenda shared with all stakeholders
- [ ] Align on pitch flow, award criteria, and jury scoring template
- [ ] Dry run with speakers if needed
- [ ] Confirm all environments are live and accessible
- [ ] Prepare printed login instructions per table
- [ ] Set up Teams channel for event materials

> ⚠️ **Field Insight:** Have the IT admin (from customer or partner) available **on-call** — not necessarily on-site — to resolve access/connectivity issues that inevitably arise. This is the "break glass person."

## PM Recommendations (Internal Microsoft)

For Partner Development Managers / Partner Technology Strategists:

| When | Action |
|------|--------|
| Framework stage | Help partner framework the event; boost visibility via [Microsoft EMEA Partner Events](https://aka.ms/EMEAPartnerEventReg) |
| Registration stage | Use [Partner Marketing Service](https://aka.ms/PartnerMarketingEventsIntakeEMEA) if partner needs logistics help |
| Use case prep | Connect partner with PSA; contact Spektra for environments |
| Presentation stage | Contact Microsoft speakers and jury members; support via [PMX](https://aka.ms/pmx) |
| Follow-up | Consolidate attending clients, share with Microsoft account teams for structured follow-up |
| O.O. Engagement | Optional: finance O.O. customer workshops through TPM budget when it can accelerate opportunity creation |
